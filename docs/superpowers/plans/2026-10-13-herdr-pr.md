# herdr-pr Implementation Plan

> For agentic workers: use superpowers:executing-plans to work through this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

Goal: build the herdr-pr plugin from the spec, as one Rust binary in `config/herdr/plugins/herdr-pr`.

Architecture: one binary with the modes `daemon`, `action`, `board`, and `link`. The daemon holds all state, talks to herdr over `HERDR_SOCKET_PATH`, and talks to GitHub through `gh`. Clients talk to the daemon over `pr.sock` in the plugin state directory.

Tech stack: Rust 1.94, tokio, serde and serde_json, regex, toml, libc, ratatui 0.30 (with its `crossterm` re-export).

Spec: `docs/superpowers/specs/2026-10-12-herdr-pr-design.md`.

## Global constraints

- One background process. Each keypress action sends one line to the daemon and exits.
- One `gh api graphql` request for each tick, for all workspaces.
- Write the `$pr` token only if its text changes.
- The fix loop prompt tells the agent to push. The daemon itself never pushes.
- Round cap: 5. Repeat cap: 2.
- Tests never touch the live herdr session. Unit tests do not open any socket.

## Review focus

1. A workspace that is not a git checkout, or has no `origin` remote, must not break the tick for other workspaces. Test: `discovery` returns `None` for a plain directory.
2. A PR that GitHub cannot find (deleted repository, no access) must show `?` for that PR only. Test: `github::parse_batch` with one null alias.
3. A herdr restart while the daemon runs must not start a second daemon. Test: a second `daemon --foreground` exits at once if the lock is held.
4. A head commit that does not change after a round must count as a repeat, not loop forever. Test: `fixloop::next_step`.
5. `gh stack view --json` fails on trunk branches ("belongs to multiple stacks"). Test: `gh_stack::parse` on that output returns `None`.
